# Аудит проекта перед доработкой (этап 0)

Состояние на 05.10.2026, коммит `fdb4372` (локальная копия совпадает с `origin/main` на GitHub).
Задание на доработку — `prompt_dorabotka.md`; плюс запрос команды: проект развёрнут на сервере,
нужна возможность обновлений через сайт.

## 1. Структура и точка входа

```
configs/  sources, panel, indicators (реестр), gmp, network, clustering, dynamics, regions
scripts/  download_data → build_inventory → build_panel → build_gmp → build_indicators → build_networks
          → fetch_external → build_clusters → build_dynamics → build_convergence;  run_all.py — всё сразу
src/      io, dictionary, bdmo, regional, panel, geo, gmp, indicators, normalize, network, clustering,
          icvi, dynamics, convergence
app/      Home.py + 6 страниц (Данные и качество, Показатели, Сеть, Кластеры, Динамика, Конвергенция), common.py
tests/    47 тестов в 7 файлах (+ дымовые тесты страниц интерфейса)
deploy/   Caddyfile;  Dockerfile, docker-compose.yml (app + caddy + профиль pipeline), DEPLOY.md
reports/  INVENTORY, DATA, METHODS, GMP_CHECKS, INDICATORS, NETWORKS, CLUSTERS, DYNAMICS, CONVERGENCE,
          OPEN_QUESTIONS, Инструктаж_аналитика.docx
```

Точка входа конвейера — `python scripts/run_all.py [--skip-download] [--quick]`; интерфейс —
`streamlit run app/Home.py`; на сервере — `docker compose up -d`.

## 3. Где жёстко задан ДФО

**Логика (меняется на этапе 1):**

- `configs/network.yaml` — `sample.federal_districts: [ДФО]` (выборка сети по умолчанию);
- `configs/indicators.yaml` — `lq_base: ДФО` (база коэффициента локализации; `lq_ru_*` уже по России);
- `configs/regions.yaml` — `default_sample: ДФО`;
- `configs/dynamics.yaml` — `samples: [ДФО, Россия]`, типы для конвергенции — «внутри ДФО»;
- `app/common.py` — переключатель выборки с ДФО по умолчанию (`sample_kind`);
- `scripts/build_convergence.py`, `build_dynamics.py` (паспорта), `build_networks.py` (имена сборок),
  `build_gmp.py` (отчёт: сверка методов, чувствительность — по ДФО), `build_indicators.py`
  (корреляции и разброс — по ДФО), `build_clusters.py` (текст отчёта);
- `tests/test_app.py` — дымовые тесты по умолчанию на ДФО.

**Остаётся как есть (ДФО — пресет/сверка):** `src/dictionary.py`, `src/panel.py` — флаг `is_dfo` в
справочнике; `configs/sources.yaml` — ВГП городов ДФО (внешняя сверка ВМП есть только для ДФО).

**Тексты:** `README.md`, `reports/*.md` (особенно INVENTORY, INDICATORS, GMP_CHECKS, CLUSTERS, DYNAMICS,
CONVERGENCE, METHODS), `Инструктаж_аналитика.docx`, подписи в интерфейсе (главная, «Данные и качество»).

## 4. Методы кластеризации

`src/clustering.py`, единый интерфейс `fit(features, graph, params) → labels`:
k-means, иерархическая Уорда, гауссовы смеси, Leiden, спектральная, KEFRiN, CANUS; индексы — `src/icvi.py`
(SW, CH, DBI, S_Dbw, AVI, AVU, ANUI, MQ).

**Связки «Уорд → k-means» нет** (есть оба метода по отдельности). Дендрограммы в интерфейсе нет.

## 5. Динамика

Оба режима уже есть: `per_year` (кластеризация каждого года + сопоставление венгерским алгоритмом по Жаккару)
и `pooled` (одна модель на все МО-годы, `clustering.fit_pooled`, только для методов по атрибутам).
По умолчанию — `pooled`, k-means, k = 6 (решение команды). **Нумерации кластеров по смыслу нет** — номера
кластеров случайные (0…k−1, порядок первого появления); названия типов задаются вручную
(`data/cluster_names.yaml`).

## 6. Поправка на цены

- **ИПЦ субъекта** (`src/indicators.regional_prices`): цепной уровень из индексов **«декабрь к декабрю»**,
  среднегодовой уровень приближён средним геометрическим уровней на декабрь двух лет; базовый год — 2017
  (параметр `base_year` в реестре); все денежные показатели получают копию `<код>_cpi`. Дефлятор только
  региональный, национального варианта нет.
- **ВМП** — отдельно: цепной дефлятор ВРП субъекта (`src/gmp.grp_deflator`), `gmp_pc_real`, база 2017.
- **Межрегиональная поправка** — только у зарплаты: `wage_real` = зарплата / стоимость фиксированного набора субъекта.
- В расчётах (сеть, кластеры) используются те колонки, которые выбраны признаками: по умолчанию
  `gmp_pc` — **номинальный** ВМП. Номинальные и реальные значения выбираются вручную; общего переключателя
  и базового года в интерфейсе нет. Конвергенция уже считается по реальным рядам.

Индексы цен, найденные в источниках (для этапа 3):

| индекс | вариант | годы | где |
|---|---|---|---|
| ИПЦ по субъектам и России | декабрь к декабрю | 2001–2024 | сборник «Регионы России» (tochno.st) |
| ИПЦ **в среднем за год** | — | **не найден** в сборниках tochno.st | нужно искать на rosstat.gov.ru |
| дефлятор ВРП | рассчитывается из ВРП и ИФО | 1998–2024 | Росстат, уже используется |
| цены на продукцию инвестиционного назначения | декабрь к декабрю | 2005–**2023** | сборник «Инвестиции» |
| цены производителей промышленных товаров (по разделам B, C, D, E) | декабрь к декабрю | 2013–2024 | «Регионы России» |
| цены производителей с/х продукции | **к предыдущему году (среднегодовой)** | 2001–2024 | «Регионы России» |

## 7. Лендинг

**В репозитории лендинга нет** (нет статического сайта, HTML или отдельного приложения; локальная копия
совпадает с GitHub). Публичная часть сейчас — только главная страница Streamlit (`app/Home.py`).
Требования этапов 1 и 7 к лендингу без него выполнить нельзя — см. вопросы ниже.

## 8. Развёртывание и обновления

Сервер: Docker Compose (`app` — Streamlit, `caddy` — HTTPS и вход по паролю, профиль `pipeline` —
пересборка данных). Данные — том `./data` на хосте; код — git-клон на сервере. Обновление сейчас —
только по SSH вручную: `git pull && docker compose up -d --build`, данные —
`docker compose --profile pipeline run --rm pipeline`. **Механизма обновлений через сайт нет.**

## 11. Вопросы, без которых дальше нельзя

1. **Лендинг.** В репозитории его нет. Он существует где-то ещё (отдельный репозиторий или файлы только на
   сервере) — тогда пришлите его или путь на сервере; или его нужно сделать с нуля (тогда это отдельная
   задача: статическая страница с методикой, картой и таблицами); или под лендингом имеется в виду главная
   страница интерфейса?
2. **«Обновления через сайт» — что именно обновлять:**
   - (а) **данные**: кнопка «пересобрать данные» (скачать свежие выпуски Росстата/СберИндекса и пересчитать
     всё) с журналом выполнения на странице;
   - (б) **код**: кнопка «обновить систему до последней версии из GitHub» (git pull + перезапуск);
   - (в) оба варианта. Кто должен иметь доступ — вся команда или отдельный администратор (отдельный пароль)?
3. **Москва, Санкт-Петербург, Севастополь** — внутригородские территории оставить как МО или агрегировать до
   города (проверю данные на этапе 1 и вынесу цифры).
4. **CANUS по всей России** — исключить из автоматической сетки «методы × k × годы» (оставить запуск
   вручную в интерфейсе) или считать на подвыборке?
