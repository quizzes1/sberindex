# Кластеризация муниципалитетов России

Конкурс СберИндекса, трек «Кластеризация». Команда Политеха Петра Великого.

Мы строим для каждого года 2014–2024 сеть муниципальных образований России (~2 600 МО верхнего уровня
в неизменных границах): узел — муниципалитет, атрибуты — экономические показатели, ребро — экономическое
сходство. На этой сети выделяем типы муниципалитетов, прослеживаем переходы между ними и собираем
сводные таблицы. Всё доступно в веб-интерфейсе на Streamlit; методологический отчёт и презентация открываются
на его стартовой странице.

- методика простым языком — [reports/METHODS.md](reports/METHODS.md);
- словарь данных и решения по склейке рядов — [reports/DATA.md](reports/DATA.md);
- развёртывание на сервере (Docker + HTTPS) — [DEPLOY.md](DEPLOY.md).

## Быстрый старт

Нужно: Python 3.11+, ~1 ГБ на диске для интерфейса (обработанные данные уже в репозитории) и ещё ~2 ГБ,
если пересчитывать всё с нуля из исходников.

```bash
git clone https://github.com/quizzes1/sberindex.git && cd sberindex
python -m venv .venv                     # или: uv venv --python 3.11 .venv
.venv/bin/pip install -r requirements.txt   # Windows: .venv\Scripts\pip install -r requirements.txt
.venv/bin/python scripts/patch_streamlit_lang.py   # страницы — на русском (иначе браузер предлагает перевод)
.venv/bin/streamlit run app/Home.py      # интерфейс: http://localhost:8501
```

Скачивать данные для интерфейса не нужно: обработанные данные, сети и результаты кластеризации лежат в
`data/processed`, `data/geo`, `data/networks`, `data/clusters`.

## Полный пересчёт с нуля

```bash
python scripts/run_all.py                # скачать исходники (~1,5 ГБ) и пересчитать всё, затем тесты
python scripts/run_all.py --skip-download --quick   # пересчитать по уже скачанным данным, без тестов и CANUS
```

| флаг | что делает |
|---|---|
| `--skip-download` | не обращаться к сети: исходники уже в `data/raw/` |
| `--quick` | без отчёта-инвентаризации, тестов и медленного метода CANUS |
| `--fast` | сетка кластеров без KEFRiN и CANUS (минуты вместо получаса на всей России) |
| `--refresh-data` | перекачать и уже скачанные исходники (при ошибке остаётся прежняя версия) |

На всей России: панель ~8 мин, ВМП ~2 мин, сетка кластеров с KEFRiN ~30 мин, остальное — минуты.
Проверка TLS не отключается: недостающие промежуточные и корневые сертификаты СберИндекса и Росстата
лежат в `certs/` с закреплёнными отпечатками SHA-256, из них и `certifi` собирается отдельный бандл.

Внешние методы KEFRiN и CANUS (Шалилех, Миркин) в репозиторий не копируются: у их репозиториев нет файла
лицензии. Нужные файлы скачиваются на закреплённых коммитах в `external/`
(`python scripts/fetch_external.py`). CANUS требует PyTorch: `pip install -r requirements-optional.txt`.

## Конфигурация: гиперпараметры в YAML

Все параметры по умолчанию — в `configs/`, у каждого параметра есть комментарий. Код их только читает.

| файл | что настраивает |
|---|---|
| `network.yaml` | выборка (вся Россия, округа, субъекты), окно лет, признаки сети и их веса, нормировка, метрика расстояния, доля географии α, вес ребра, прореживание (kNN + остовное дерево, k соседей) |
| `clustering.yaml` | методы кластеризации и их гиперпараметры (`n_init`, ковариация GMM, подбор разрешения Leiden, параметры KEFRiN/CANUS), диапазон k, `seed`, порядок нумерации K1…Kn |
| `dynamics.yaml` | разбиение по умолчанию (режим pooled/per_year, метод, k = 5), нумерация типов по годам, бутстрэп, ряды и окна конвергенции |
| `indicators.yaml` | реестр показателей (формула, источник, единица, логарифм, индекс цен) и параметры цен: базовый год, индексы по России или по субъектам, межрегиональная поправка |
| `gmp.yaml` | расчёт ВМП: индикаторы распределения ВДС по отраслям, годы методов, варианты чувствительности |
| `summary.yaml` | сводные таблицы: пороги описаний кластеров, периоды по умолчанию, цвета траекторий |
| `panel.yaml` | сборка годовой панели: какие ряды БДПМО брать, как суммировать и чем заполнять пропуски (только с флагом) |
| `sources.yaml` | источники данных: адреса, коды показателей, сертификаты |
| `regions.yaml` | пресеты выборки (федеральные округа) |

Параметры сети входят в её хэш: сеть с другими параметрами сохраняется в свой каталог
`data/networks/{hash}/` вместе с `params.json`.

## Как воспроизвести результат

Настройки по умолчанию в `configs/` — те, на которых построены методологический отчёт и презентация: вся Россия
без МО, менявших границы; 2014–2024; признаки — ВМП на душу, зарплата, инвестиции без бюджета, отгрузка,
бюджетная самостоятельность; min-max по всей панели; евклидово расстояние; kNN (5 соседей) + остовное дерево;
цены 2020 года по общероссийским индексам с поправкой на цены регионов; «Уорд + k-means», 5 типов, одна модель
на все годы. С ними `streamlit run app/Home.py` и `python scripts/run_all.py` дают те же числа, что в отчёте
(например, в 2014 г. сеть из 1 900 узлов и 6 506 рёбер, типы K1–K5 — 136, 243, 606, 432 и 483 МО).

- **Из интерфейса.** Под таблицами на каждой странице есть кнопка «Скачать параметры (YAML)»: в файле все
  настройки боковой панели, параметры сети и разбиения. Те же значения, перенесённые в `configs/`, дают тот же
  результат: случайность везде зафиксирована (`seed: 42`).
- **Из кода.** Пример — `notebooks/01_quickstart.ipynb`:

```python
from src import clustering, icvi, network, summary

p = network.merge_params(network.default_params(), {"features": {"gmp_pc": 1, "wage": 1}, "sparsify": {"k": 5}})
nets = network.build(p)  # {год: YearNetwork}: nets[2022].edges(), .stats()
labels = summary.partition(p, "ward_kmeans", 5, "pooled")  # territory_id, year, label (0 → K1)
X, W = nets[2022].X.to_numpy(), nets[2022].W * nets[2022].A
icvi.compute_all(
    X, W, clustering.fit(X, W, {"method": "ward_kmeans", "k": 5})
)  # SW, CH, DBI, S_Dbw, AVI, AVU, ANUI, MQ, WCSS
```

## Конвейер данных

| шаг | скрипт | результат |
|---|---|---|
| загрузка | `download_data.py` | исходники в `data/raw/` (вне git), `SHA256SUMS`, `FAILED.txt` |
| инвентаризация | `build_inventory.py` | `reports/INVENTORY.md` |
| панель | `build_panel.py` | `data/processed/panel_*.parquet`, `mo.parquet`, полигоны `data/geo/` |
| ВМП | `build_gmp.py` | `gmp*.parquet`, `reports/GMP_CHECKS.md` |
| показатели и цены | `build_indicators.py` | `indicators*.parquet`, `price_levels.parquet`, `reports/INDICATORS.md` |
| полнота данных | `build_data_gaps.py` | `reports/DATA_GAPS.md`, таблицы покрытия |
| сети | `build_networks.py` | `data/networks/{hash}/`, `reports/NETWORKS.md` |
| кластеры | `build_clusters.py` | метки и индексы для k = 2…10 × методы × годы, `reports/CLUSTERS.md` |
| динамика | `build_dynamics.py` | переходы, устойчивость, бутстрэп, `reports/DYNAMICS.md` |
| конвергенция | `build_convergence.py` | σ- и β-конвергенция, клубы, `reports/CONVERGENCE.md` |
| сводные таблицы | `build_summary.py` | `reports/SUMMARY.md`, Excel и версия для печати |

Ключ панели — `territory_id × year`. Для среза по году (сеть, кластеры) берутся строки `valid_in_year`;
строки `derived` — достроенные значения прошлых лет для преемников объединений, они нужны только динамике.
Пропуск — это скрытое или неопубликованное значение: нули вместо пропусков не подставляются.

ВМП (валовой муниципальный продукт) — **наша расчётная оценка**, а не данные Росстата: ВДС субъекта по
отраслям распределяется между его МО по отгрузке, продукции сельского хозяйства и отраслевому ФОТ.

Денежные показатели хранятся в текущих ценах и переводятся в цены базового года (по умолчанию 2020) своим
индексом цен: потребительские цены, дефлятор ВРП, цены инвестиционной продукции, цены производителей.

## Интерфейс

`streamlit run app/Home.py`. Слева меню:

- **Отчёт и презентация** (стартовая) — методологический отчёт и презентация с просмотром на сайте,
  скачиванием PDF и ссылкой на GitHub;
- **Обзор** — что где смотреть, цены, типы муниципалитетов и переходы по субъектам с текущими настройками;
- **Данные и качество** — полнота данных по годам и субъектам, пропуски, сравнение с работой-образцом, индексы цен;
- **Показатели** — описания, распределения, корреляции, карта;
- **Сеть** — признаки и веса, география, связи; сеть на карте и в силовой раскладке;
- **Кластеры** — режим, метод (в т.ч. «Уорд + k-means» с дендрограммой), число типов, карта, профили типов,
  индексы качества, метод локтя, сравнение методов, названия типов;
- **Динамика** — переходы между типами (Санки), размеры типов по годам, устойчивость, кто куда перешёл;
- **Сводные таблицы** — описания типов (можно поправить вручную) и переходы по периодам на уровне МО и
  субъектов, с выгрузкой в Excel;
- **Обновление данных** — скачать свежие данные и пересчитать результаты прямо с сайта.

Настройки боковой панели (территория, годы, нормировка, цены) общие для всех страниц и сохраняются при
переходе между ними. Страница «Конвергенция» временно скрыта из меню; код — `app/pages/6_Конвергенция.py`.

## Тесты и качество кода

```bash
python -m pytest -q        # 124 теста: данные, ВМП, цены, сеть, индексы, методы, динамика, сводные таблицы, интерфейс
ruff check . && ruff format --check .
```

Тесты проверяют, например: сумма ВМП по МО субъекта равна ВРП; при общероссийских индексах цен смена
базового года не меняет кластеров; индексы AVI/AVU совпадают с эталонной реализацией авторов; каждый метод
кластеризации восстанавливает заданные группы; при одинаковых параметрах размеры кластеров совпадают на всех
страницах интерфейса.

## Как расширять

**Добавить показатель.**
1. Запись в `configs/indicators.yaml`: код, название, формула, источник, единица, блок, `log`, `direction`;
   для денежного — `monetary: true` и `deflator` (cpi | grp | invest | ppi_industry | ppi_manufacturing |
   ppi_agri) — без дефлятора тест не пройдёт.
2. Функция с тем же именем в `src/indicators.py`: принимает `Context`, возвращает `Series` с индексом
   `(territory_id, year)`. Нужен новый исходный ряд — добавьте его в `configs/sources.yaml` и `configs/panel.yaml`.
3. `python scripts/build_indicators.py`.

**Добавить метод кластеризации.**
1. Функция `_fit_<имя>(X, W, p) -> labels` в `src/clustering.py` (X — нормированные признаки, W — веса рёбер,
   p — параметры, в т.ч. `k` и `seed`).
2. Запись `<имя>: {family: attributes | graph | attributed_network, ...}` в `configs/clustering.yaml` и строка
   в `FAMILIES`.
3. Имя в списке `METHODS` в `tests/test_clustering.py` — тест проверит метод на трёх разделимых группах.
